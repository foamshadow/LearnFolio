# docs 写回触发与收口清单（proposal）

## 背景

项目以文档为主，文档管理的现状是"有规则、散且不全"：写回规则散落在四份文档
的五六个角落，各自盯不同的信号源，且有明确盲区——是否更新同步全靠执行 agent
自觉与评审 agent 是否发现。

### 两类漂移的生成机制（仓库实例对号）

| 漂移类型 | 生成机制 | 本仓实例 |
| --- | --- | --- |
| 复述漂移 | 下层文档复述真源/实现的事实，真源变了复述没跟上 | `guides/ci-gate.md` filters 清单滞后 C4（PR #62 修正）；SPEC-0001 A5 文本滞后 #27（执行差异记账） |
| 真源分叉 | 同一规则在两处都写成"真源"口吻 | ADR-0003 vs AGENTS 分支节（deprecated + 锚点分级注记止血——"以 AGENTS 分支节为准"，非指针化；毕业指针化先例是 merge-integrity proposal）；AGENTS 七类 vs learn 提案九类（进行中） |
| 事实性错述 | 写作时凭记忆断言现状，未核对实现 | learn 提案 r1 对 merge.sh 判定的错述（PR #61 B1）；毕业伪引（#60 B5） |
| 引用腐烂 | 引用的文档/结论失效（毕业、重写） | "merge-integrity P0 阶梯"伪引——毕业指针化副作用 |
| 变更不同步 | 一次语义变更要同步 N 处复述点，无枚举手段 | "变更链同 PR 同步"存在，但改的人不知道 N 是多少 |

关键观察：**漂移是"复述"的属性**。真源自己不会漂；漂的是复述它的地方。

### 现状规则散点与盲区

| 规则 | 定义在哪 | 盯什么 | 盲区 |
| --- | --- | --- | --- |
| SPEC 写回窗口（PR 创建后、评审通过前：变更记录/验收/实测） | AGENTS 文档体系节 | 任务 PR | 无——最完善 |
| 收口冻结 + 文档对齐核对 | AGENTS 继承条款 | **Phase 收口** | 任务级无对应物 |
| 变更链同 PR 同步 | AGENTS 继承条款 | spec 变更 | 只盯 spec 起点 |
| guides 维护触发器 | docs/README.md 真源层级节 | **AGENTS/ADR 的 PR** | 盯错对象——实现变更（ci.yml / merge.sh / 脚本）不触发，C4 漂移正是此类 |
| 新增 ADR 补决策线行；词表变更改 README | README 决策线/扩展规则 | 毕业、新词表 | 靠记忆 |
| 事故当天或最近 PR 内记 journal + 落条款 | AGENTS 继承条款 | 事故 | learning 何时写未定义 |
| journal 边界 = 最后一次 push（方案甲） | #60 journal 规则素材（待转正） | 任务 journal | 未成为正式规则 |
| 面板刷新（每次合并 PR 后） | 面板自身说明 | 合并 | 仓库外文件，规则不在仓库 |

### 三个洞（本 proposal 的靶心）

1. **guides 触发器覆盖面错**：只盯 AGENTS/ADR 的 PR；漂移的真正源头常是
   实现变更——这类 PR 不碰 AGENTS/ADR，触发器永远不响。
2. **任务级收口（合并授权停点）没有文档检查项**：停点表 #9 只有"人工授权"，
   文档对齐全靠自觉。
3. **learning / 尾随更新没有决定点**：事故后谁判定写不写 learning？合并后
   发现要更新 guide 合法吗？——全无规则。

## 提议

### 1. 事件形式化

写回时机的"行" = 任务生命周期 **10 步流程**（docs/proposals/task-lifecycle-gates.md：
①确认任务 → ②开发 → ③整理门 → ④dev-review → ⑤commit → ⑥push → ⑦PR 创建 →
⑧pr-review → ⑨合并请求 → ⑩收尾；注意其停点表 #1–#10 与流程步骤**不一一对应**，
⑩收尾明文非停点）+ 4 个全局事件：**事故 / 毕业（proposal adopted）/ Phase 收口 /
破坏性操作（retract、force push）**。矩阵行轴按写回视角聚合：开发期（②–⑥）、
PR 创建（⑦）、pr-review（⑧）、合并请求（⑨）、收尾（⑩）+ 4 全局事件独立成行
（事故不折进任务行）。

### 2. 写回矩阵（事件 × 文档）

● 必写（硬约束）／◐ 判据触发／— 不适用。**⑨ 合并请求不设写回格**——它是
清单 1 的**核验**停点（见 §3），写入动作应已于窗口内完成。

| 事件 | AGENTS | SPEC | ADR | guides | proposals | journal | learning | README |
| --- | - | - | - | - | - | - | - | - |
| ① 确认任务 | — | — | — | — | ◐ 新想法入孵化 | — | — | — |
| ②–⑥ 开发期（开发/整理门/commit/push） | ◐ 条款 | ◐ 验收修订 | ◐ 新决策 | ◐ | — | ◐ 任务 journal 初稿（随 ⑥ 首推入分支） | — | — |
| 事故（全局） | ◐ 条款 | ◐ 验收修订 | ◐ 新决策 | ◐ | — | ● 事故当天记 | — | — |

| ⑧ pr-review | ◐ 评审暴露缺口则窗口内补 | ◐ 窗口内补账 | ◐ | ◐ | ● 演进记录追加 | ◐ 每轮 REVIEW-FIX = amend 末尾 docs commit（搭同一 push） | — | ◐ 登记面缺口窗口内补 |

矩阵是"何时必须写"的总图；逐任务执行靠 §3 清单 1（矩阵的任务级投影）。
SPEC 的"PR 号记账行 / CI 实测结果"落 **⑦–⑧ 窗口内**（PR 号在 PR 创建时已知，
AGENTS 窗口条款现行口径），⑨ 之后即为执行差异通道——不存在合并落地写回行。

### 3. 合并请求停点清单（清单 1，五项）

清单 1 的自查区**随写回窗口增量维护**（预先性记录原则，§5），至 **PASS 前
完整**；合并请求（人工停点，tlg 流程 ⑨ = 停点表 #9「合并授权」）上人工
**核验**自查区终态，不再写入——PASS 后描述冻结（评审协议），此时写入 =
作废 PASS。授权核验发现缺口 → 补提交 → 重新 PASS（快照重取）→ 再授权，
成本回环由停点承担：

| # | 核验项 | 判据 |
| --- | --- | --- |
| 1 | SPEC 窗口闭合 | 变更记录 / 验收勾选 / 实测结果齐（既有规则的核对） |
| 2 | 复述面 | 本 PR 改变的事实/规则 → grep AGENTS + guides → **窗口内更新**，或记录**"无需更新"**（一句话理由） |
| 3 | 登记面 | 新 ADR → README 决策线行；新词表值 → 词表行；触及 proposal 陈述 → 演进记录 |
| 4 | journal 封账 | 边界 = 最后一次 push；无 journal → 说明理由 |
| 5 | 终态就位 | 触及的状态字段（SPEC/proposal status、README 状态行）窗口内已增量维护至差一步终态；合并只落终态标记 |

**可执行性抓手（时点锚）**：凡文档复述现状的句子必须带来源锚
（`随 #NN 落地` / 真源文件名）——清单 1 第 2 项从"agent 判断是否触及"变为
`git grep "#NN" docs/`，机械可执行。

### 4. Phase 收口扩展清单（清单 2）

在清单 1 基础上追加全量盘点：guides 全量 vs 实现逐篇对齐（不再只 grep 本
PR）；收口 journal 事故清单如实完整（learning 的被动可见性载体，见 §6）；
README 词表复核；PR 模板与 AGENTS 条款对齐抽查。

### 5. 预先性记录原则

状态与完成描述字段**随窗口增量维护，合并时只落终态标记**——"已完成"的正文
在窗口内写好，合并这个动作本身只负责把状态翻成终态。反面实例：SPEC-0001 验收
勾选在收口前置 PR #47 一次性回填；README 状态行 #21 才从"Phase 0 待启动"改
进行中。此原则封死"合并后补一篇 docs PR 做完成回填"的路径（那属于执行差异）。

### 6. learning 例外（成员自主）

learning/<作者键>/ 是**成员个人内容**（作者键目录、"谁经历谁写"语义、
learn-branch-workflow 的回收物）：**项目不设写回触发器**——写不写、何时写由
成员决定。项目侧唯一合法动作是**被动可见性**：收口 journal 的事故清单如实
完整（本就是记账纪律），成员自己对号。"教训可泛化"是项目视角，不作为成员
写作的门槛。

### 7. 二值判定（无尾随通道）

**写回边界 = 合并授权；边界外发现 = 新事件（执行差异），走已有通道，不设
"登记后续补"。** 清单 1 第 2 项是二值判定：窗口内更新，或明确记录"无需更新"
（一句话理由）——不存在第三态。

理由（与 journal 写回时机讨论同构）：**事件边界决定写回边界**——journal 的
边界 = 最后一次 push，边界外的事 = 新事件新 journal，从不尾随追加到已封账的
事件上；docs 同构。尾随通道的四个纠缠：①窗口侵蚀（合法尾随 = 写回窗口的
逃生舱）；②语义双轨（与执行差异条款撞车，账本无法区分"计划补"与"漏掉"，
搅浑过程改进信号）；③漂移窗口合法化（登记 ≠ 执行，尾随期 = 制度化的
"文档与事实不对应"）；④"合入后才知道"的类别经盘点近乎不存在——PR diff
完全决定合并后的现实，guide 写的是将要成为现实的行为；真合入后观测
（dev push 红）本身是事故，有自己的事件与通道。

### 8. journal 写回与审查记账（随本 proposal 毕业转正）

#60 journal 规则素材六条中的四条已具备转正条件（三次 docs 任务实弹
#59/#60/#61，不依赖代码任务演练），随本 proposal 毕业落档：

- **journal 写回边界（方案甲）**：随任务分支的 journal 边界 = 最后一次
  push；PASS 与合并执行属边界外（评论层 + PR 状态 + merge.sh 落地核验承载）；
  合并中撞出的新事实走下一个事件的 journal。粒度 = 提炼教训 + 评论层索引，
  不逐轮复述（#60 即该规则的首个实例——边界外结构讨论自成一篇 journal）。
- **序列结构不变量（docs 收尾部分）**：写 journal 的任务序列以 docs 型提交
  收尾（AGENTS/journal 同步），功能提交在前。
- **trailer 严格语义 + journal 审查记录表**：trailer 只声明"当前树被谁审
  过"，反对跨版本累加旧审查者（语义失真、与失效语义冲突、行内无法标注版本）；
  版本级审查历史由 journal「审查记录」表承载（#60 首发实例，格式随毕业登记
  journal 模板）。
- **amend 预检判据（docs 分支已验证）**：纯文档 commit（`docs:` 前缀 + 仅
  文档文件）amend → 不预检、删旧 trailer 转移 PR 级；评审期间 journal 每轮
  更新 = amend 末尾 docs commit（搭同一 push，零额外消耗）。**功能提交预检
  与 fixup 轻量复核分支未经实弹**，转正文本标注"待 task-lifecycle-gates
  毕业演练验证"。

剩余两条（整理门不强制重组、force push 降档）+ amend 判据的代码分支依赖
**task-lifecycle-gates 毕业批**（演练矩阵验证后），与本 proposal 互不触碰。

### 9. 毕业落点

本 proposal 毕业为**双落点**（同批 PR），按"决策还是细节"分流水（沉淀三问②；
二值判定与预先性记录属**决策级**——自带被否方案与翻转条件，其"为什么"须
住 ADR 决策线可查，不随指针化埋没）：

- **新 ADR（编号起草时分配）收决策级**：事件边界决定写回边界（含二值判定
  及其四个纠缠的被否方案）、预先性记录原则、journal 写回与审查记账（方案甲
  边界 / 序列不变量 docs 收尾 / trailer 严格语义 + 审查记录表 / amend 预检
  判据 docs 分支）。ADR-0006 不动（新增不冲突，非取代）。
- **AGENTS「文档写回」条款收操作级**：清单 1/2 执行条款（五项核验判据）、
  learning 成员自主例外（**显式声明澄清现行"事故驱动笔记"描述语**——项目
  不设触发器，写作归成员，避免制造新的复述漂移）、时点锚纪律、终态就位
  操作细则。
- **审查记录表格式 → journal `_template.md` 登记**（#60 首发样例为范本）。
- **清单 1 自查区 → PR 描述模板**（随窗口维护的占位区）。
- **README 决策线表追加新 ADR 行**（清单 1 第 3 项登记面的自我适用）。
- **#60 journal 遗留节追加注记**：四条已转正（宿主新 ADR）、两条 + amend
  代码分支仍随 task-lifecycle-gates 毕业版。

### 10. 演进口（本次不做）

- **机器对账六条**（frontmatter 词表合法性、draft 编号文档禁引用、取代链
  完整性、目录登记三件套、分支前缀词表三处对账、merge message 变体对账）：
  清单跑熟后机械化（ci:docs 首批内容——AGENTS 验证命令节已预留坑位）。
- **清单 1 进 pr-meta 校验**：先 AGENTS 条款 + PR 模板自查区，跑数任务看
  遵守率再决定是否机器挡（docs 任务逐项强制会显啰嗦）。
- **时点锚的全量回填**：先约束增量（新复述必带锚），存量回填随各文档自然
  修订顺路。

### 11. 被否的替代设计

- **尾随 docs PR 合法化（登记后续补）**：§7 四个纠缠——被二值判定取代。
- **learning 项目判据（教训可泛化 → 写）**：项目视角强加个人学习，违背
  作者键领地语义——被 §6 成员自主例外取代。
- **全量 docs-as-tests**：不可机检的散文强行测 = 脆弱断言；只对账"要命且
  可机检"的事实（演进口六条），其余归清单与审计。
- **事实 ID 登记簿**（每条事实编号、消费方引用 ID）：5 人团队维护不过来，
  时点锚以近零成本达到近似可枚举性。
- **纯审计兜底**（定期 sweep 不改触发器）：滞后——发现时已漂 N 个 PR；
  审计保留为清单 2 的收口形态而非独立机制。

### 12. 毕业条件

- 本 proposal 的主体是**既有实践的收编**：journal 边界/审查表/amend docs
  分支三次实弹（#59/#60/#61）；清单 1 的第 1/4 项为现行规则核对、第 3 项为
  散点规则收编。新增机制（复述面 grep、二值判定、终态就位）自本 proposal
  合并后的**下一个任务**起生效，首次应用后 journal 记执行反馈。
- 评审 PASS → 毕业批 PR（§9 五个落点同批）→ 复盘无结构性缺陷即维持
  adopted；若首用发现结构性问题，修订后重审（不回滚收编部分——它们本就是
  现行规则的显式化）。
