## 教训

1. **位置即语义**。规则被放在「破坏性操作」节、夹在两条约束句之间，agent 按小节主题归类为"临动手才查"。无条件启动动作与条件约束并列，就会被读成约束的附注。
2. **长会话衰减是真实的失效模式**。AGENTS.md 会话启动时一次注入；数十轮无关工作后切入仓库任务，注意力焦点在技术细节，流程前置项被挤出。"规则在上下文里"≠"规则在注意力里"。
3. **我给出的第一个诊断是错的**。人类问"是否需要加强引导"，我先想到加措辞——但事故中 agent 并非没读懂。措辞强度不解决注意力调度；改的是位置与触发。
4. **我给出的第一个方案也是错的**。把阶段规程放进 `docs/guides/`，被人类以"guides 是人类读的、含基础知识、对 agent 冗余"否决——正确。且 pi 不自动加载 docs/ 下任何文件，What 落那里等于靠 agent 想起来，与事故同构。
5. **docs 提交确认不随 auto-commit 豁免——这是已定规则，不是开放问题**。本篇初稿把 #68 第二个提交（`95376e1`）的处理写成"两种读法都通"的存疑项，经评审（#69 B2）指正：ADR-0007 变更记录 2026-11-18 已明文「**D5 规则本身不变**（docs 提交始终确认，不受 auto-commit 影响）……确认的是内容，不是提交数」，tlg 停点表 #2 与 AGENTS 操作分级同向，三处规则文本一致——"auto-commit 的告知语义覆盖 docs 确认"这一读法无任何文本依据。故 `95376e1` 是本事件的**第二处违规**，不是歧义。真正的开放点只剩**确认的粒度 / 形态**：逐提交停问，还是授权与确认同批（#69 的 `c8ab76c` 按后者，D5"确认的是内容"支持）。教训：把已定规则写成"存疑"，实质是为自己的违规找台阶——比违规本身更该警惕。
6. **渐进披露有上限**。"启动时申请授权"是会话行为，没有钩子可拦——只能靠位置 + 触发。能被机制兜底的靠机制（`commit-msg` 校验 trailer 已是范例），不能的如实记为局限。
7. **评审者席位要提前备**。herdr-collaboration 规定了 `rv` 命名即登记，但池子是空的——需要评审时才发现无可指派席位。池化生命周期（§5）若不常态运行，"升级人类"会成为每次的默认路径。
