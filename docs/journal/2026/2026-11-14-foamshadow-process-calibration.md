# 流程校准日

> agent 起草、人审定（作者键 = 审定者）。本篇记录建仓次日的一次集中校准：
> 一天之内，合并策略、文档体系、协作授权与遗产继承全部落定。

## 事件

首提交缺 agent 署名触发第二次重建；随后在真实使用中连续撞出四个边界：merge 提交无法带
trailer、GitHub 的账本行会追加 PR 号、docs 变更不该长分支、提交与推送缺少授权约束。
每个边界都在当天沉淀为 ADR 或 AGENTS 条款，并各由一个 PR 验证。

| 时间 | 事件 |
| --- | --- |

## 决策

### 二次重建，而不是继续改写
首提交已成基线，但早期两条 docs 变更走的是 merge，留下了分支节点；规则改为 squash 后，
旧节点成了反例。趁仓库只有 4 件产物、零协作者，删库重建一次性把历史线性化——代价是
PR 记录消失，收益是形状与规则一致。这是最后一次为形状重建；冻结线之后只走 ADR。

### docs 走 squash，任务走 --no-ff
docs 通常只有一个提交，merge 节点不携带过程信息；squash 让 dev 第一父链回到
"任务节点 + 文档单提交"的读法。代码任务保留 `--no-ff`，因为过程提交是学习材料。

### 授权拆成两个开关
auto-commit 与 auto-push 分开申请：前者管"能否不等确认地提交"，后者管"能否把本地推出去"。
WIP 免审，因为它是草稿；docs 不受 auto-commit 影响，因为它没有 rebase 整理机会。

### t4 提前
继承条款的消费者（提交规则、分支纪律、验证门）当天就在写；再等会把规则写两遍。
判据固定为三条：工具无关、对 5 人团队成立、有消费者。

## 异常

- **squash 主题被追加 ` (#N)`**：与 merge 提交一致，账本读法与后续校验需容忍该后缀。
- **squash 后 `git branch --merged` 识别不到已合分支**：SHA 被重写，本地分支应直接删。
- **`gh pr merge` 因 token 缺 `read:org` 失败**：改用 REST merge，结果一致。
- **工作区出现 `.mimosa/` 本地状态目录**（hook-state）：已加入 `.gitignore`。

## 遗留

- t0 未开工（CI 骨架、六变体正则、非 merge 署名 job）。
- 二次重建将把 dev 线性化，去掉两个早期 docs merge 节点，PR 记录随之消失。
- 继承条款中"测试左移"等留待 t2。

## 复盘

规则与实现的飞轮在一天里转了两圈：实现撞出边界 → ADR 定结论 → AGENTS 落条款 →
下一条 docs PR 验证。代价是规则密度上升、历史被改写；冻结线（v0.1.0）之后不再重建，
改为纯 ADR 演进。
