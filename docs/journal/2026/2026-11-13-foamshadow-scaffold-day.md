## 决策

### 首提交重做，而不是追加一个"补署名"提交

首提交是基线：补后续提交能让"以后"有署名，但第一条提交永远没有。当时仓库只有一个
提交、零 fork、零他人克隆，重做成本最低；等有人 clone 之后再改，就要向所有人解释历史
改写。**撤回的最佳时刻是现在，其次是更早。**

重做取"重建仓库根"而非改写后续：旧对象不留在新仓，也不依赖平台回收。

### opt-out 署名，且与首个使用者同时到达

`Assisted-by: <harness>:<model>`，纯人类提交写 `none`。opt-in 下 CI 只能校验格式、不能
校验存在性——漏写永远查不出来，本次事故正是这个洞。规则本体（AGENTS + ADR）留到建仓后
的规则 PR，但提案随首提交入库：首提交自身按规则署名，既无空窗，也不引用尚不存在的文档。

### `required_approving_review_count = 0`（临时）

单协作者下 1 approval 与 `enforce_admins=true` 组合成死锁（不能自批、管理员也不能
绕过）。第二位成员加入后提为 1；收口仍按 ≥1 非作者核心。

### merge 主题取 PR 标题、正文留空；required checks 暂空

账本行只承载 PR 标题，正文噪音不入 main 第一父链。`ci-ok` 尚未上报，设置界面下拉
选不到，按"先合入后补配"：t0 合入后立即补，否则 CI 从 day 0 退化为"跑了但没人拦"。
