# ADR-0008：遗产继承与裁剪

> 补记说明：本篇对应 SPEC-0001 任务 t4（遗产整理），因提交与协作规则的消费者已在建仓次日到达，
> 提前于 t0 执行；输入为 harmony-wechat 的 AGENTS.md 与软工流程复盘、foampray 的 AGENTS.md。

## 背景（Context）

- 两个前序项目可继承：harmony-wechat（16 天、8 里程碑、239 提交、两次历史重写、事故→制度闭环）与
  foampray（pnpm monorepo 全站，技术栈与本项目接近）。
- 风险同样明确：鸿蒙 168 行 AGENTS 对"16 天两人项目"已超配（其复盘自认）；大量条款绑定 ArkTS / DevEco /
  superpowers 插件；其"commit 即评审点"的前提是无 PR 门禁，与我们的模型相反。
- t4 原排在任务序列后段，但其消费者（提交规则、分支纪律、验证门）现在就在写；不提前会双写、双真源。

## 决策（Decision）

### D1 三条判据（全部通过才继承）

1. 工具无关——不绑定 ArkTS / DevEco / 特定插件；
2. 对 5 人团队成立——不是一人课程的临时约定；
3. 有消费者——现在或最近一个任务有落点；没有消费者不预支。

### D2 三类处置 + 来源规则

直接继承（语义不变）/ 改写继承（按 PR 门禁改写）/ 不取（工具特定、课程语境、无消费者）。
每条继承条款注明来源；与既有条款冲突时以既有条款为准。

### D3 直接继承（6 条）

| 条款 | 来源 |
| --- | --- |
| 事故→制度闭环：事故当天或最近一次 PR 内，journal 记事故 + 落一条带判据的条款 + 关联 PR | H §提交纪律 / 复盘 |
| 第一父链 = 任务账本：只允许任务 merge 与 docs 单提交 | H §分支纪律 |
| 收口冻结 + 文档对齐核对：文档不得落后于代码，先改文档再合并 | H §里程碑收口 |
| 变更链同 PR 同步：改 spec 同批改下游文档与验收 | H §文档驱动 |
| 注释写"为什么"；TODO 落码，不留在聊天记录 | H §注释要求 |
| 验收如实记账：受限 / 跳过 / 缺失都入账 | H 复盘 |

（"一个 commit = 一个逻辑单元""push 前自查""消息不写'修复上次'"三条已由 ADR-0007 与既有提交纪律覆盖，不重复。）

### D4 改写继承（2 条）

| 原条款 | 改写为 | 备注 |
| --- | --- | --- |
| 里程碑表 + 收口流程 | roadmap + SPEC + 收口检查单 | 保留；收口流程后续可优化，Phase 0 收口前再定 |
| 计划=事实（checkbox / 裁定注） | 验收条目按实际勾选、不虚报；**执行差异记入当次 journal**（journal 记完整经历，差异只是其中一类）；规格语义变化另走 spec 变更记录 | 不新增"裁定注"渠道 |

（提交确认、push 指令、未完成不提交、docs 直推、feature 命名五条已由 ADR-0005 / 0007 落档，不重复。）

### D5 不取（5 条）

superpowers 插件链；ArkTS / DevEco 命令与单模块结构；课程语境的项目概述；PERT 图（Phase 0 无并行任务）；
双 README 分工（本项目已有根 README + docs/README）。

### D6 只作判据、不落条款（4 条）

两次历史重写（攒批的代价）、规范滞后 3 天（支持"随消费者到达"）、条款密度超配（裁剪判据）、
测试左移不足（t2 后再议）——记入本篇背景与被否方案。

### D7 时间与验收

t4 提前到现在执行；SPEC-0001-A9 的"裁剪 + 继承决策 journal"提前满足（journal 为 2026-11-14 事件篇）；
foampray 的技术细节（pnpm hoist、Tailwind v4 等）归 t1/t2，不入 AGENTS。

## 被否方案（Alternatives）

| 方案 | 否决理由 | 翻转条件 |
| --- | --- | --- |
| 全盘照搬鸿蒙 AGENTS | 168 行对 5 人项目超配；大量条款绑定 ArkTS / DevEco / 插件 | 技术栈与工具链完全一致 |
| 只取技术约定、不取流程 | 丢掉"事故→制度闭环"与账本读法，而那正是最有价值的部分 | — |
| 推迟到 t4 原位置 | 消费者已到，先写半套再改一遍 = 双写 | — |
| 每条注来源但不裁剪 | AGENTS 膨胀，后人无法判断哪条仍成立 | — |

## 后果（Consequences）

- AGENTS 增加"继承条款"节（约 30 行），每条带来源，可追溯可再裁剪；
- t4 提前消化，任务序列剩余 t0–t6；A9 提前满足；
- 改写条款与原项目语义不同（WIP、推送、确认），条款内注明"按 PR 门禁改写"；
- 未取条款不是否定，而是"当前无消费者"，需要时按 D1 判据重新评估。
