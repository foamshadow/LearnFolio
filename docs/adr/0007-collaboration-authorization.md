# ADR-0007：协作授权模型

> 补记说明：决策定于 2026-11-14，与遗产裁剪（ADR-0008）同日；粒度判据继承 harmony-wechat 的提交纪律，
> 按本仓库的 PR 门禁改写。破坏性操作清单沿用 ADR-0003 后果节，本 ADR 只调整 commit / push 的授权方式。

## 背景（Context）

- 现行 AGENTS 写"agent 可自主 commit、push（非 force）"，等于没有可见性约束：agent 可静默连提多个提交、
  直接推送，开发者只能事后看历史。
- `docs/*` 分支没有 rebase 整理机会（恰好一个提交、squash 即落地），提交即发布；代码分支有 PR 前的整理兜底。
- harmony-wechat 的"commit 即评审点"（提交前人工确认、push 凭指令）建立在其**无 PR 门禁**的前提上，不能原样照搬；
  但其"一个 commit = 一个完整逻辑单元"的粒度判据可继承。
- WIP 与"每个提交可编译"直接冲突，必须划分适用范围。

## 决策（Decision）

### D1 操作分级

| 档 | 操作 |
| --- | --- |
| 自主 | 读、改工作区、查看 |
| 告知 | 本地 commit（获得 auto-commit 时） |
| 逐条审批 | 未获 auto-commit 时的提交（`wip:` 免审） |
| 确认 | `docs/*` 提交（无 rebase 兜底） |
| 许可 | push（未获 auto-push 时逐次）、合并 PR、tag、force、`rebase -i`、`revert -m` |

### D2 任务启动的双授权

创建任务分支、说明任务内容后，一次性申请两项**独立**授权：

- **auto-commit**：授予后提交前告知即可，不等确认；未授予则逐条审批（WIP 除外）；
- **auto-push**：授予后任务内所有 push 免逐次审批，每次 push 后报告；未授予则每次单独许可。

两项授权均为**任务级**：任务结束失效，可随时撤销。

### D3 WIP 免审

即使未获 auto-commit，`wip:` 前缀提交也免审批——WIP 是草稿不是交付；只有锚点与整理后的提交需要审批。
WIP 仍须提交前告知。

### D4 告知内容

所有提交前说明：改了什么、为什么、涉及几个提交。auto-commit 省的是"等待"，不是"告知"。

### D5 docs 提交确认

`docs/*` 无整理机会（squash 即落地），提交前给**文件清单 + 关键点**并取得同意；不受 auto-commit 影响，始终确认。

### D6 可编译边界

- WIP：不要求可编译，允许推送（任务分支不触发 CI）；
- 锚点（一个可验证步骤）：应编译过 / 测试绿；
- PR 整理后保留的每个提交：必须可编译（bisect 可用）；
- 合入 dev / main：必须绿（CI 保证）。

### D7 提交粒度

一个提交 = 一个完整逻辑单元：单一意图（功能 / 修复 / 重构 / 文档 / 构建不混）；纯格式化与重命名单独提交；
小改动攒批随所属单元；禁止"补一行"式碎片；消息不写"修复上次的…"。

### D8 无人在场

默认：本地 WIP 提交、**不推送**、恢复后报告，并补申请两项授权。

## 被否方案（Alternatives）

| 方案 | 否决理由 | 翻转条件 |
| --- | --- | --- |
| 逐条审批制（每提交都等） | 我们没有 commit 时的人工在场，PR 才是评审点；逐次审批阻塞 agent 吞吐 | 任务风险极高（如首次发布）可临时提升为逐条 |
| 维持全自主 | 静默连提、越权推送，开发者失去可见性 | — |
| push 全自主 | 发布不可逆，许可成本低于误推成本 | 出现只读镜像等安全机制 |
| 每提交必须可编译 | 与 WIP 直接冲突，逼 agent 把工作藏在工作区 | 放弃 WIP 文化 |
| docs 与代码同规则 | docs 无 rebase 兜底，提交即落地 | docs 改为多提交 + rebase 整理 |

## 后果（Consequences）

- 授权两开关增加一次启动对话，换来任务内零打断与全程可见；告知与许可靠纪律与会话实践，CI 只覆盖合并态。
- WIP 免审可能让红提交出现在任务分支历史；分支不跑 CI、PR 前会被 fixup，不影响共享线。
- docs 的确认往返是刻意的：它是唯一没有整理机会的载体。
- 需同步修改 AGENTS"破坏性操作"与"提交纪律"两节及 guides（告知与授权的操作方式）。

## 变更记录

- 2026-11-18：ADR-0010 撤销“docs/* 分支恰好一个提交”约束后，D5 的机制前提（“docs 无整理机会、squash 即落地、提交即定稿”）失效——docs 分支现可多提交。**D5 规则本身不变**（docs 提交始终确认，不受 auto-commit 影响）。保留确认的现行理由：docs 是可直接被引用的真源（spec / ADR / guide / journal），错误内容的传播成本高于代码；squash 落地后的修正要走评审、必要时还要 rewrite。确认的是内容，不是提交数。本条同时覆盖正文嵌入该前提的各处——背景（Context）节、D1 表“确认”档的括注、D5 的机制括注、被否方案对照表“docs 与代码同规则”行的理由列、后果节“它是唯一没有整理机会的载体”——正文不可变，以本条为准（缺口发现于 t3 评审，见 journal `2026-11-18-foamshadow-t3-commit-hooks.md` §7）。
